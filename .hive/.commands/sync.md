# /sync — Analyst Agent
<!-- tokens: ~1700 | loads: analyst.md -->

**Usage:** `/sync`
Run at: sprint start, after major PRD changes, when sprint scope changes.

---

## Role
Regenerates `.hive/specs/SPEC.md` by pulling live data from the configured
ticket board and combining it with PRD and Architecture documents.

---

## Process

### Step 0: Read configuration
Read `.hive/AGENTS.local.md`:
- `ticket_provider.tool` and `ticket_provider.mcp_name`
- `ticket_provider.statuses.*` — status names for categorization
- `ticket_provider.board_url`
- `fallbacks.ticket_unavailable`

### Step 1: Read local specs
Extract from:
- `.hive/specs/PRD.md` — problem (2–3 sentences), goal (1 sentence)
- `.hive/specs/ARCHITECTURE.md` — module list
- `.hive/AGENTS.local.md` — project name, ticket key

### Step 2: Fetch sprint data

**MCP available** — use the configured tool:

```
# Jira (Atlassian MCP):
getActiveSprint(projectKey)
getIssuesInSprint(sprintId)

# Linear (Linear MCP):
getCycles(teamId)           → active cycle
getIssues(cycleId)

# GitHub Issues (GitHub MCP):
listIssues(owner, repo, labels=["sprint-current"])
# Note: GitHub doesn't have native sprints — use milestone or label

# ClickUp (ClickUp MCP):
getActiveSprints(spaceId)
getTasks(sprintId)
```

**MCP unavailable** → follow `fallbacks.ticket_unavailable`:
- If `"ask"` → ask user to paste a list of current sprint tickets (ID + title + status)
- If `"skip"` → generate SPEC.md with a note that sprint data could not be fetched

### Step 3: Categorize tickets
Use the exact status names from `ticket_provider.statuses.*`:

```
In Progress → statuses.in_progress
Ready       → statuses.refined (or statuses.backlog if no refined status)
Done        → statuses.done
Blocked     → statuses.blocked (if configured, else check for "blocked" label)
```

### Step 4: Generate SPEC.md

Output to `.hive/specs/SPEC.md`:

```markdown
# SPEC.md — {project name}
_Generated: {ISO timestamp}_
_Ticket board: {ticket_provider.tool} | Branch: {vcs.default_base_branch}_

> Auto-generated by /sync. Do not edit by hand.

---

## Context
{2-3 sentences from PRD: problem + goal}

---

## Sprint: {sprint/cycle/milestone name} ({start} → {end})

Board: {ticket_provider.board_url}

### In Progress
- [ ] **{ticket-id}** [{S|M|L}]: {summary}
  - Assignee: {name}

### Ready for Development
- [ ] **{ticket-id}** [{S|M|L}]: {summary}

### Done This Sprint
- [x] **{ticket-id}**: {summary}

### Blocked
- 🔴 **{ticket-id}**: {summary}
```

### Step 5: Commit
```bash
git add .hive/specs/SPEC.md
git commit -m "chore: sync SPEC.md from {tool} sprint {name}"
```

---

## Story point → size mapping
- ≤ 2 points → S
- 3–5 points → M
- 6+ points → L
- No estimate → M (default)

## Notes
- GitHub Issues has no native sprint concept — use milestones or a label like `sprint-current`
- Trello has no story points — all tickets default to M
- Linear calls sprints "cycles"
- ClickUp has native sprints with story points
